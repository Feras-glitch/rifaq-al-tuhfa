# دليل المطوّر

## الملفات
- `Student_App_v9.18.html`: التطبيق بالكامل في ملف واحد (HTML + CSS + JS). يعمل بالمنشأ `file://` دون خادم.
- `Developer_Studio_v9.18.html`: الاستوديو. يضمّن قالب التطبيق في المتغير `EMBEDDED_STUDENT_TEMPLATE_B64` (Base64) ويصدّر الحزم بإعادة كتابة كتلة `PACK_DATA`.
- `curriculum/framework/`: أدوات الأنواع التفاعلية (`qx_core.js`، `qx_ui.js`، `qx.css`، `qx_validate.js`) وسكربت المزامنة `sync_qx.py`، واختبارات المتصفح.

## تدفق البناء
1. تعديل الإطار التفاعلي في `framework/` ثم `python3 sync_qx.py Student_App.html Developer_Studio.html`.
2. يعيد السكربت تضمين القالب في الاستوديو. التحقق: `EMBEDDED_STUDENT_TEMPLATE_B64` يفك إلى الملف الخارجي بايتًا بايت.
3. تحديث `APP_VERSION` في التطبيق والاستوديو معًا.

## التخزين (IndexedDB و localStorage)
- **`localStorage`**: الحالة الصغيرة (STATE): الهوية، والتقدم، والإعدادات، والموافقة الأبوية. المفتاح مُشتق من `PACKAGE_ID` ومن اسم الطالب.
- **قاعدة الصوت** `tohfa_student_audio_<packageId>_<hash>`، مخزن `audios`: تسجيلات الطالب كـ Blob، مفتاحها معرّف العنصر. الاسم يعتمد على اسم الطالب، فالتسجيلات لا تختلط بين الأطفال.
- **قاعدة المفاتيح** `tohfa_teacher_keys`، مخزن `keys`: مفتاح توقيع المعلم (CryptoKey غير قابل للتصدير مع JWK عام). **واحد لكل المتصفح**، لا لكل طفل.
- لا يوجد أي مسح شامل للمخزن (لا `clear()`)، فالمفاتيح لا تُفقد عند تنظيف تسجيلات.

## تدفق الأدوار
- `detectMode()` و`boot()` يحددان الدور من `PACK_DATA.packageType` قبل أي `localStorage`.
- **التسجيل** (`startRec`): يمر أولًا بالتحقق من الاعتماد، ثم بالموافقة الأبوية (`ensureConsent`)، ثم يبدأ المسجّل، ومعه مؤشر الصوت (`startLevelMeter`) وحد المدة (`REC_MAX_MS`) ومراقب الانقطاع (`track.onended`، `visibilitychange`، `rec.onerror`).
- **الاعتماد**: `exportApprovedPack` يستدعي `teacherSigningStatus` ثم `buildAndDownload(approved)`، فيوقّع `signGiftPack` البيان قبل التسلسل.
- **التحقق**: `boot` يستدعي `verifyGiftPack` للإهداء، ويضع `GIFT_TRUST` ويعرض شارته عبر `giftTrustBadge`.

## صيغة الجنسين
- `GT(text)` تستبدل `{مذكر|مؤنث}` حسب `STATE.student.gender`. تُطبَّق على شرح الدرس، ونص السؤال، والتلميح، والتعليل، وصيغ QX، والاستخراج.

## الاختبارات (متصفح Chromium آلي، Playwright)
تُشغَّل من مجلد `t/` ويحتاج كل منها ملفات HTML مولّدة بـ `mkpack.make(source, out, pack)`:
| الملف | يغطي |
|---|---|
| `t_consent.py` | بوابة الموافقة، حفظها، تصديرها، ورفض الاسم القصير |
| `t_limits.py` | حد المدة، تنبيه الصمت، إيقاف عند مغادرة التطبيق |
| `t_partial.py` | علامة التسجيل الناقص من التسجيل حتى عرضها للمعلم |
| `t_teacher_consent.py` | سطر الموافقة في شاشة المعلم، ووجوده وغيابه |
| `t_sign.py` | الحالات الخمس للتوقيع (valid، untrusted، tampered، unsigned، status_flip) |
| `t_sign_status.py` | حالات توقيع المعلم الأربع |
| `t_studio_trust.py` | قبول مفاتيح الاستوديو وتعقيمها |
| `t_gender.py` | صيغ الجنسين للطفلة والطفل |
| `t_kids.py` | الدورة الكاملة: تسجيل، مراجعة بملاحظة، إعادة، اعتماد |
| `t_qx.py` | حل كل الأنواع التفاعلية، ومسار الأخطاء، وحقن خبيث |
| `t5.py` | حقن الحزمة الخبيثة وتعقيمها |

النتيجة المعيارية: لا `Traceback` ولا `pageerror`. بعض الاختبارات تعرض حوارًا متوقعًا (رفض بلا تعليق، أو تأكيد الإصدار).

## فحص الكود الثابت
- لا دوال مكررة (تحقق بالتعبير النمطي).
- لا روابط خارجية في الملف.
- سياسة CSP تمنع أي اتصال شبكي.

## قيود معروفة
- لا خادم، فكل شيء محلي.
- التأنيث في واجهات التطبيق الثابتة (مثل «أحسنت») تُراجع مع المراجع.
- الاختبارات على متصفح آلي بميكروفون وهمي، ولم تُجرَ على هاتف حقيقي.
- المخارج والصفات والجزرية لم تُنفذ بعد.
